# Fund Performance Tracker

Автоматично месечно проследяване на взаимни фондове и ETF-и: сваля историческите
цени на дял (NAV) в SQLite, симулира покупки по 10 EUR на всяко 15-то число и
публикува HTML отчет с доходността по месеци и години за всеки фонд.

**Отчет:** след включване на GitHub Pages е на адрес
`https://vislupus.github.io/fund-performance-tracker/`

## Какво прави

На 1-во число на всеки месец (и при ръчно стартиране) GitHub Action:

1. сваля новите цени за всеки фонд от `config/funds.yaml` през няколко източника
   (Financial Times → Investing.com → BAMOSZ / Morningstar, по ред) и ги записва в
   `data/funds.sqlite`;
2. импортира ръчно свалени CSV файлове от `data/manual/`;
3. експортира историята на всеки фонд в `data/csv/<ISIN>.csv` (удобно за Excel);
4. изчислява доходности, риск и DCA симулация и генерира `docs/index.html`;
5. commit-ва резултата и публикува страницата в GitHub Pages.

Отчетът съдържа:

| Раздел | Съдържание |
|---|---|
| Моят портфейл | Симулация на плана „10 EUR във всеки портфейлен фонд на 15-то число“ от датата в `settings.yaml`: вложени, стойност, печалба, XIRR, графика стойност/вложени |
| Преглед на фондовете | YTD, 1/3/5 г., от начало (годишна), волатилност, максимален спад, DCA XIRR; сортируема таблица |
| Доходност по години | Таблица фонд × календарна година с цветова скала |
| Сравнение | Всички фондове приведени към 100 за избран период, с бенчмарк (MSCI World) |
| Фондове по отделно | Цена на дял, DCA от самото начало на фонда, месечна доходност (heatmap), покупки по плана, симулация по години |
| Данни и източници | Какво е успяло/провалило при последното обновяване |

## Първоначална настройка

1. **GitHub Pages:** Settings → Pages → Source: *GitHub Actions*. (Workflow-ът
   опитва да го включи сам; ако репото е частно, Pages изисква платен план –
   тогава просто отваряй `docs/index.html` от репото.)
2. **Първо изпълнение:** Actions → *Monthly fund update* → *Run workflow*.
   При първия пуск се сваля цялата история (може да отнеме няколко минути).
3. Провери раздела *Данни и източници* в отчета. За фондове, за които всички
   източници са се провалили, свали CSV ръчно и го сложи в `data/manual/`
   (виж `data/manual/README.md`).
4. Редактирай `config/settings.yaml` → `my_plan_start` с датата на първата си
   реална покупка, за да съвпада раздел „Моят портфейл“ с твоя план.

## Конфигурация

* `config/funds.yaml` – списъкът с фондове. Всеки има `isin`, `name`, `currency`,
  `group` (`portfolio` / `watchlist` / `benchmark`), по желание `entry_fee_pct`
  (входна такса, която се удържа в симулацията), `providers` (ред на източниците)
  и `ids` (подсказки, ако автоматичното търсене по ISIN хване грешен клас дялове).
* `config/settings.yaml` – сума и ден на покупка, начало на плана, курс BGN/EUR.
* `data/transactions.csv` – по желание реалните ти покупки (дата, ISIN, сума,
  дялове, цена). Ако има редове, отчетът показва реалния резултат до симулацията.

## Локално изпълнение

```bash
pip install -r requirements.txt
export PYTHONPATH=src
python -m fund_tracker update            # сваля данните (или: update --isin LU0106235533 --full)
python -m fund_tracker report            # генерира docs/index.html
python -m fund_tracker status            # какво има в базата
python -m fund_tracker reset HU0000733472   # изтрива данните за фонд (напр. при грешен клас)
python -m unittest discover -s tests     # тестове
```

## Източници на данни

| Източник | Как | Покрива |
|---|---|---|
| Financial Times (`markets.ft.com`) | търсене по ISIN → xid → `get-historical-prices` | повечето UCITS фондове и ETF-и |
| Investing.com | мобилно API (`aappapi.investing.com`) с резервен `tvc6` канал; приема само резултати, носещи ISIN-а | резервен вариант |
| BAMOSZ (`bamosz.hu`) | bulk download servlet (`data.download`) по ISIN – пълна история от старта на фонда | унгарските OTP фондове |
| Morningstar (legacy time-series API) | SecId по ISIN | резервен вариант |
| Ръчен CSV | `data/manual/<ISIN>.csv` (BAMOSZ, Investing.com или дата;цена) | всичко |

Сайтовете нямат официални API-та и могат да променят формата си. Затова всеки
фонд се опитва през няколко източника, всеки опит се логва, а провалите не
спират обновяването на останалите фондове.

Проверено при разработката (октомври 2026): 10-те портфейлни фонда, 5-те
наблюдавани LU фонда/ETF-а и бенчмаркът се свалят автоматично (OTP през BAMOSZ,
останалите през FT). За **ДСК Баланс** и **ДСК Растеж** няма публичен източник с
история, който да работи автоматично – `dskam.bg` показва историята само през
JavaScript форма. За тях свали справката „Нетна стойност на активите на дял“ от
dskam.bg (Инвестиционен помощник → фонд → период) и я сложи в
`data/manual/BG9000004051.csv` / `data/manual/BG9000004069.csv`.

Забележка: за Amundi Funds Global Equity / Global Multi-Asset / China Equity FT
дава история от 2000–2001 г., т.е. включва предшественика (Pioneer Funds), от
който класът е създаден през 2019 г. Отчетът го отбелязва при фонда.

Workflow-ът *Tests* съдържа и job `live-data-smoke`, който при всеки push сваля
данните в временна база, без да записва нищо – полезно, за да видиш веднага кой
източник работи.

## Методика (накратко)

* **Доходност на фонда** = промяна на NAV; без входни такси и данъци.
* **DCA симулация**: на `purchase_day` (или първия следващ ден с цена през същия
  месец) се купуват дялове за `monthly_amount` по цената за деня.
* **XIRR** = годишна доходност, претеглена по пари – това, което реално усещаш
  като инвеститор при месечни вноски.
* **Волатилност** = годишно стандартно отклонение на месечните доходности.
  **Макс. спад** = най-голямото падане от връх до дъно.
* BGN фондове се преизчисляват в EUR по фиксирания курс 1.95583.

Миналото представяне не гарантира бъдещи резултати. Това е личен инструмент за
анализ, не инвестиционен съвет.
